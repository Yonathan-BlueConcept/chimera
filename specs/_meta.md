# System Meta

## Vision

The purpose of this project is to provide a reliable, agentic execution
framework that integrates with the VS Code Chat system and converts user
input into verifiable, structured tasks.

The system is designed to emphasize:
- Deterministic task decomposition
- Explicit execution steps
- Validation and retry mechanisms
- Clear separation of agent responsibilities

The long-term goal is to serve as a foundation for building controlled,
auditable AI agent workflows rather than ad-hoc prompt execution.

---

## Core Design Principles

### Agentic Separation
Each agent has a single, well-defined responsibility:
- Planning
- Execution
- Verification

Agents must not overlap responsibilities or bypass each other.

### Reliability Over Speed
The system prioritizes correctness and verifiability over fast execution.
Task persistence and validation are mandatory steps.

### Spec-Driven Behavior
System behavior is defined by written specifications.
Code must conform to the specs, not the reverse.

### AI-as-a-Component
LLMs are treated as interchangeable components, not sources of truth.
All LLM output must be validated before being accepted by the system.

---

## Constraints

### Input Constraints
- All user input enters the system through the VS Code Chat interface.
- Direct invocation of agents outside this flow is not supported.

### Execution Constraints
- All tasks must be generated by the Planner.
- All tasks must be written to `tasks.json` by the Worker.
- Tasks are not considered valid until verified by the Judge.

### State Constraints
- `tasks.json` is the single source of truth for generated tasks.
- No additional persistent storage is required or assumed.

### Runtime Constraints
- The system runs inside a Docker container.
- Runtime configuration must not rely on host-specific state.

---

## Non-Goals

- Autonomous agent self-modification
- Unbounded tool execution
- Long-term memory or knowledge storage
- User identity or session management
